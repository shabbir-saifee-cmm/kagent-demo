Advanced classifier patterns

Where a cheap classifier call beats a workflow

Pre-merge

Platform-rules CI check

On every PR, one low-cost “System 1” Jev call reads the diff against the platform's guardrails — naming conventions, workload identity over static credentials, forbidden patterns — and flags violations before a human reviewer looks at it. No agent loop, no tools: one prompt in, a pass/fail with a reason out.

Planning cadence

Sprint-fit scoring

“Which sprint does this ticket belong in?” A classifier call scores a ticket's readiness, dependencies and size against the current and next sprint during refinement, surfacing a recommendation instead of a human eyeballing the backlog by hand.

On-call

Support ticket routing

Classify an incoming ticket as platform-owned vs. app-team-owned and route it to the right queue automatically, removing a manual triage step from the on-call rotation.

One prompt in, a structured label out. The cost of being wrong is a missed label, not a bad deploy — so the cheapest capable model is the right default here.

In-cluster development

Your companion harness doesn't have to live on your laptop

The coding harness you work beside all day doesn't need one engineer's laptop to stay open — it can run as a workload inside the cluster. Here it's the DeepSeek harness.

DeepSeek harness running in-cluster — session view

Handoff: resuming the same session from a different device

Session persists independent of a laptop sleeping, closing or disconnecting — pick the session back up from any device.

Unlocks “overflow tasks”: opportunistic backlog work that doesn't need a named individual driving it, since the harness runs under a team or service identity rather than a personal laptop session.

When the harness is a platform workload, its usage is metered and billed against a team/project budget rather than routed through one developer's personal seat or API key.
